# Anonymizer Proxy — Резюме проекта

> 📖 **Таблица терминов** размещена в конце документа — см. [раздел «Термины»](#термины).

## Что это такое

**Anonymizer Proxy** позволяет использовать облачные LLM без раскрытия чувствительных данных третьим лицам или работать с чувствительными данными локально.

**Anonymizer Proxy** — это локальный прокси-сервер на FastAPI, который располагается между клиентом (Cline, Hermes) и LLM-бэкендом:

- облачной моделью ИИ (OpenRouter, GPTunneL, BotHub, AITUNNEL, GenAPI и др.)
- или локальной моделью (доступной через LM Studio).

Его задача — при необходимости анонимизировать (NER) файлы в запросах, отправлять запрос/файлы в облако, получать ответы и в нужный момент деанонимизировать полученные файлы, а также позволить работу с локальной моделью без анонимизации.

Пользователь может

- отправить промт/файлы сразу без анонимизации, - если они не содержат чувствительных данных
- анонимизировать файлы (т.е. получить версии в которых фамилии, названия, суммы и пр. заменены плейсхолдерами), просмотреть/отредактировать их,
- отправить в облако один или несколько промтов в анонимизированном виде, всякий раз получая текст ответа облачной модели и, возможно, измененные файлы, которые остаются анонимизированными
- деанонимизировать в любой момент полученные файлы результата
- кроме того пользователь может работать с локальной моделью, не пользуясь анонимизацией

В конце сценария с анонимизацией/деанонимизацией в папке лежат рядом:

- оригинальный файл
- анонимизированный оригинальный файл
- деанонимизированный файл конечного результата всех запрошенных в ходе сессии манипуляций.

В конце сценария без анонимизации - только исходный файл и файл результата.

Облачные модели доступны через OpenRouter с использованием VPN или через одного из российских провайдеров (бета-версия) : GPTunneL, BotHub, AITUNNEL, GenAPI — без VPN
Локальные модели доступны через LM Studio, - OpenAI-совместимый сервер.

Переключение между облачной и локальной моделями производится на лету командой в чате, например:

- 'переключись на ботхаб' переключится на BotHub
- 'работай через aitunnel'  переключится на AI-tunnel
- 'переключи бэкенд на гптуннел'  переключится на GPtunnel
- 'верни опенроутер'  переключится на OpenRouter

Для конфиденциальных данных, которые модель должна видеть (например, суммы в Excel), выбирайте локальный бэкенд — тогда данные не покинут машину.

Анонимизация всегда выполняется локально (через модели GLiNER + Natasha, встроенные в прокси).

Прокси работает с OpenAI-совместимым клиентом, выполнена адаптация под Cline (расширение
VS Code) и Hermes Agent (см. соответствующие разделы ниже).

## Быстрый старт

### Предварительные требования

Для работы понадобятся:

1. **Аккаунт OpenRouter** и ключ API — https://openrouter.ai/keys (ключ
   вводится один раз при установке или записывается позже в файл `.env`
   с перезапуском прокси)
   и/или **Аккаунт и ключ одного или нескольких российских провайдеров**
2. **Внешний VPN-прокси для доступа к OpenRouter** — в связи с санкциями,
   введёнными против РФ. Подходит любой локальный HTTP/SOCKS5-прокси
   (например, Happ); адрес указывается в `.env` (`OPENROUTER_PROXY`).
   Альтернатива (бета): российские провайдеры — GPTunneL, BotHub, AITUNNEL, GenAPI, Chad API — работают **без VPN**, напрямую; см. раздел «Облачные провайдеры»
3. **Клиент — на выбор** (подключается к прокси после его установки, см.
   разделы «Подключение клиента» ниже):
   - **Cline** — AI-ассистент, расширение VS Code (потребуется VS Code:
     https://code.visualstudio.com/download). Рекомендуемые дополнительные
     расширения: **Open in External App** (открытие файла в приложении по
     умолчанию), **Office Viewer** (просмотр MarkDown и MS Office в окне
     VS Code);
   - **Hermes Agent** (Nous Research) — установка описана в разделе
     «Подключение Hermes Agent»

Один и тот же прокси обслуживает любого из клиентов — можно подключить
и оба одновременно.

#### Системные требования

| Параметр                              | Windows                                                  | macOS                                        |
| --------------------------------------------- | -------------------------------------------------------- | -------------------------------------------- |
| ОС                                          | Windows 10/11, x64                                       | macOS 12+ на Apple Silicon (M1–M4)        |
| Оперативная память           | от 8 ГБ (рекомендуется 16)              | от 8 ГБ (рекомендуется 16)  |
| Свободное место на диске | от 10 ГБ (рекомендуется 20)             | от 10 ГБ (рекомендуется 20) |
| GPU (необязательно)              | NVIDIA → CUDA; AMD/Intel → DirectML; без GPU — CPU | ускорение через Metal (MPS)    |

Установщик проверяет требования перед началом установки: при их невыполнении
он останавливается с соотв. сообщением, при частичном соответствии
(например, 8–16 ГБ ОЗУ или мало места) — предупреждает и продолжает.

Прокси распространяется через **GitHub Releases** (zip-архив репозитория).
Установка — одним скриптом: он сам ставит Python (через `uv`), подбирает
зависимости под ваше железо, скачивает NER-модели, создаёт файл конфигурации
`.env` (установщик предложит ввести ключ OpenRouter) и проверяет результат.

### Windows (CUDA / AMD / CPU)

1. Скачайте и распакуйте zip-архив релиза.
2. Запустите **`install.cmd`** двойным кликом (именно `.cmd`, а не `.ps1` —
   если что-то пойдёт не так, см. ниже «Если установщик не запускается»).
3. Скрипт автоматически:
   - снимет блокировку «скачано из интернета» с распакованных файлов;
   - установит `uv` (если его нет) и нужную версию Python;
   - определит ускоритель: NVIDIA GPU → `onnxruntime-gpu 1.24.4` + CUDA-DLL из
     pip; иначе → `onnxruntime-directml` (AMD/Intel GPU, NPU);
   - создаст `.env` из примера, сгенерирует `PROXY_API_TOKEN` и предложит
     ввести `OPENROUTER_API_KEY`, ключи других провайдеров нужно ввести вручную в файле .env;
   - скачает NER-модели (GLiNER + Natasha) и выполнит самопроверку;
   - создаст ярлык «Anonymizer Proxy» в меню Пуск.

Запуск после установки: **`start_proxy.cmd`** (или ярлык в меню Пуск).

Сервер стартует в **отдельном окне консоли** (заголовок окна —
«anonymizer-proxy»), логи видны в нём. Это защищает прокси от случайного
Ctrl+C в терминале, из которого выполнен запуск: событие Ctrl+C доставляется
только процессам своей консоли, а кнопка **Cancel** в Cline отправляет
Ctrl+C в терминал, где выполняется `start_proxy.cmd` (без отдельного окна
это останавливало прокси). Остановка: закрыть окно сервера или нажать
Ctrl+C внутри него. Запуск в текущей консоли (прежнее поведение):
`start_proxy.cmd --foreground`.

#### Если установщик не запускается

Windows блокирует скрипты, скачанные из интернета (Mark of the Web).
Типовые ошибки при попытке запустить `install.ps1` напрямую:

- **«выполнение сценариев отключено в этой системе»** (политика Restricted) —
  запускайте не `install.ps1`, а `install.cmd`: он вызывает PowerShell с
  параметром `-ExecutionPolicy Bypass`, который действует только для процесса
  установки и системные настройки не меняет.
- **«файл не имеет цифровой подписи»** (политика RemoteSigned требует подпись
  для файлов из интернета) — `install.cmd` сам снимает эту метку командой
  `Unblock-File`. Вручную это делается любым способом:
  - ПКМ по `install.ps1` → «Свойства» → внизу поставить галочку
    **«Разблокировать»** → OK;
  - или в PowerShell: `Unblock-File .\install.ps1`.
- **Ошибка содержит «не может быть переопределена политикой, заданной на этом
  компьютере»** — политика выполнения задана групповой политикой организации
  (обычно AllSigned). `-ExecutionPolicy Bypass` её не обходит; обратитесь
  в IT либо на время установки выполните в PowerShell от администратора:
  ```powershell
  Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
  .\install.ps1
  ```
- Альтернатива без PowerShell вообще: откройте `install.cmd` в любом текстовом
  редакторе и выполните описанные в нём шаги вручную (или воспользуйтесь
  WSL/Linux-подобной средой со скриптом `install.sh`).

### macOS (M1–M4)

1. Скачайте `anonymizer-proxy-<версия>-macos.zip` из релиза и распакуйте.
2. Откройте **Терминал** (Terminal) и перейдите в распакованную папку:

   ```bash
   cd ~/Downloads/anonymizer-proxy-<версия>-macos   # путь к распакованной папке
   ```
3. Запустите установщик:

   ```bash
   ./install.sh
   ```
4. Скрипт автоматически:

   - проверит системные требования (Apple Silicon, macOS 12+, ОЗУ, место на
     диске) и остановится с понятным сообщением, если их выполнить нельзя;
   - установит `uv` (если его нет — одной командой curl) и нужную версию
     Python;
   - поставит зависимости CPU-варианта (`uv sync --locked --extra cpu`);
   - создаст `.env` из примера, сгенерирует `PROXY_API_TOKEN`, пропишет
     `NER_DEVICE=mps` и предложит ввести `OPENROUTER_API_KEY` (с проверкой
     формата; Enter — пропустить и вписать позже);
   - скачает NER-модели (GLiNER + Natasha) и выполнит самопроверку;
   - создаст ярлыки запуска: **Anonymizer Proxy.app** (в папке проекта) и
     `start_proxy.command` (двойной клик — окно Терминала с сервером); в
     конце спросит, включать ли автозапуск при логине (по умолчанию — нет).

Запуск после установки: двойной клик по **Anonymizer Proxy.app** — он уже
лежит в папке проекта. Один раз перетащите его в папку «Программы» и/или в
Dock — и запуск станет доступен оттуда одним кликом (путь к проекту зашит
внутри ярлыка, поэтому в «Программах» может лежать именно копия). Если в
дальнейшем переместите папку проекта — пересоздайте ярлык:
`bash make_mac_app.sh`. Подробности и альтернативы — в разделе
«Запуск и остановка прокси» ниже.

Если shell сообщит «Permission denied», выполните `bash install.sh` —
скрипту не требуется бит исполнения.

На macOS официальный пакет `onnxruntime` собран только под CPU, поэтому ставится
CPU-вариант; ускорение на Apple Silicon даёт PyTorch-фоллбэк через Metal (MPS) —
установщик прописывает `NER_DEVICE=mps` в `.env`.

#### Если установщик на macOS не запускается

- **«Permission denied»** при `./install.sh` — запустите через интерпретатор:
  `bash install.sh` (бит исполнения не нужен) либо дайте право один раз:
  `chmod +x install.sh`.
- **«cannot be opened because the developer cannot be verified»** — macOS
  пометила скачанные файлы меткой quarantine. Снимите её из папки проекта:
  `xattr -dr com.apple.quarantine .` — и повторите запуск.
- **Ошибка preflight** («Требуется Apple Silicon», «Требуется macOS 12+»,
  «Недостаточно оперативной памяти», «Мало свободного места») — условия
  обязательные, см. таблицу «Системные требования» выше.

### Запуск и остановка прокси

**Запуск** — в зависимости от ОС:

- Windows: ярлык **«Anonymizer Proxy»** в меню Пуск или `start_proxy.cmd`
  (сервер откроется в отдельном окне консоли; остановка — закрыть окно или
  Ctrl+C в нём; `start_proxy.cmd --foreground` — запуск в текущей консоли);
- macOS: **ярлык уже создан установщиком** — `Anonymizer Proxy.app` лежит
  в папке проекта. Один раз перетащите его в «Программы» и/или в Dock —
  дальше запуск одним кликом (можно оставить копию в «Программах»:
  путь к проекту зашит внутри ярлыка). Двойной клик открывает окно
  Терминала с логами сервера; остановка — Ctrl+C в этом окне. Работает и
  Терминал: `./start_proxy.sh` (если «Permission denied» —
  `bash start_proxy.sh`);
- Linux: в Терминале перейдите в папку проекта и выполните
  `./start_proxy.sh`.

**Страница настроек при запуске ярлыком.** Ярлык (меню Пуск Windows,
`Anonymizer Proxy.app` / `start_proxy.command` на macOS) помимо сервера
открывает и экранную форму настроек **`/env-editor`** в браузере по
умолчанию:

- если прокси ещё не запущен — сервер стартует в своём окне (Терминале),
  а страница настроек откроется автоматически, когда он будет готов
  (первая загрузка NER-модели может занять до минуты);
- если прокси **уже запущен** — второй экземпляр не поднимается: просто
  открывается страница настроек (в macOS-окне Терминала нажмите Enter,
  чтобы закрыть его);
- закрытие страницы настроек прокси **не останавливает** — остановка
  только через окно сервера (Ctrl+C) или закрытие этого окна.

**macOS, дополнительные варианты:**

- **Запуск без ярлыка** — двойной клик по `start_proxy.command` в папке
  проекта тоже открывает окно Терминала с сервером (если Finder предлагает
  открыть файл в редакторе, один раз выполните
  `chmod +x start_proxy.command`);
- **Ярлык пересоздать/удалить** — `bash make_mac_app.sh`
  (создаёт `Anonymizer Proxy.app` в папке проекта заново;
  `bash make_mac_app.sh remove` — удалить);
- **Автозапуск при логине** — `bash install_launchagent.sh` ставит
  LaunchAgent (`~/Library/LaunchAgents/ru.anonymizer.proxy.plist`): сервер
  стартует сам при входе в систему и перезапускается при падении
  (KeepAlive), логи — `data/logs/proxy_launchagent*.log`
  (`bash install_launchagent.sh remove` — отключить). Установщик
  предлагает включить его в конце установки; по умолчанию выключен,
  т.к. прокси держит ресурсы (ОЗУ под NER-модель) всё время работы Mac.

При старте в консоли появляется баннер с режимом и NER-бэкендом:

```text
[OK] NER-движок загружен (onnx (CUDAExecutionProvider, CPUExecutionProvider))
Uvicorn running on http://127.0.0.1:8081
```

**Проверка работоспособности:**

Windows (PowerShell):

```powershell
Invoke-RestMethod http://127.0.0.1:8081/health
```

macOS/Linux (curl):

```bash
curl http://127.0.0.1:8081/health
```

Поле `ner_backend` показывает фактический бэкенд инференса:
`onnx (CUDAExecutionProvider, ...)` — NVIDIA GPU; `onnx (CPUExecutionProvider)` —
CPU (в том числе весь macOS-вариант; ускорение на M1–M4 даёт `torch (mps)`);
`torch (...)` — аварийный фоллбек (см. WARNING в логе запуска).

**Остановка:** `Ctrl+C` в окне прокси (или просто закройте окно/вкладку
Терминала).

> Чрезвычайная мера, если прокси завис и не реагирует: `taskkill /f /im python.exe`
> (Windows) или `pkill -f python` (macOS/Linux). Завершает ВСЕ python-процессы
> машины — используйте только когда иначе никак.

### Подключение клиента 1: Cline (расширение VS Code)

Прокси сам по себе не имеет интерфейса чата — к нему подключается клиент.
Оба поддерживаемых клиента настраиваются одинаково просто: указывается
адрес прокси, всё остальное (реальные модель и ключ OpenRouter) хранится
в `.env` прокси и клиентам недоступно.

- прочие расширения, упомянутые в «Предварительные требования» установите по аналогии

Нажмите на иконку расширений в левой панели, найдите по имени и установите **Cline**.

Откройте появившуюся вкладку **Cline** в левой панели VS Code и настройте провайдера:

| Поле | Значение                                                       |
| -------- | ---------------------------------------------------------------------- |
| Base URL | `http://127.0.0.1:8081/v1`                                           |
| API Key  | любое значение (прокси его игнорирует) |
| Model    | любое значение                                            |

Прокси использует только свои настройки из `.env` (реальную модель и ключ);
то, что указано в Cline, игнорируется. Стриминг модели, если он есть, - поддерживается (`Stream: true`).

Затем установите **правила анонимизации** — они объясняют Cline
соглашение о «копии-исходнике / `.result`-файле» и работу с плейсхолдерами.
Правила берутся **из папки проекта**:

- **Правила этого проекта уже на месте** — файл `.clinerules` в корне папки
  прокси. Cline читает его автоматически, когда эта папка открыта в VS Code,
  ничего копировать не нужно.
- **Для другого проекта**, в котором будете работать с документами, установите
  правила из папки проекта:

  ```powershell
  Set-Location '<путь-к-прокси>'
  .venv\Scripts\python.exe scripts\install_rules.py <путь-к-проекту> --clinerules
  ```

  Это создаст `<проект>\.clinerules` (и, заодно, `AGENTS.md` для Hermes —
  см. «Подключение клиента 2»).

> Глобальные правила Cline (весы → Rules в панели Cline, каталог
> `%USERPROFILE%\Documents\Cline\Rules\`) больше не обязательны: правила
> конкретного проекта имеют приоритет и действуют ровно там, где обрабатываются
> документы. Добавляйте их только если хотите, чтобы правила анонимизации
> действовали в **любой** открытой папке.

### Подключение клиента 2: Hermes Agent (Nous Research)

Прокси работает с [Hermes Agent](https://github.com/NousResearch/hermes-agent)
как обычный OpenAI-совместимый endpoint: Hermes отправляет запросы на прокси,
прокси перехватывает команду анонимизации и передаёт в облако только
обезличенный текст. Установка на машину пользователя сводится к четырём шагам.

#### Шаг 1. Убедитесь, что прокси запущен

```powershell
Invoke-RestMethod http://127.0.0.1:8081/health
```

Поле `status` должно быть `healthy`. Прокси должен работать до запуска сессии
Hermes (ярлык **«Anonymizer Proxy»** в меню Пуск).

#### Шаг 2. Настройте провайдера в Hermes

Откройте `config.yaml` в домашней папке Hermes:

- Windows (десктоп-установщик): `%LOCALAPPDATA%\hermes\config.yaml`;
- остальные варианты установки: `~/.hermes/config.yaml`.

Приведите блоки `model` / `providers` к виду:

```yaml
model:
  default: anonymizer-proxy    # имя произвольное — прокси его игнорирует
  provider: anonymizer_proxy
  base_url: http://127.0.0.1:8081/v1
  context_length: 128000       # прокси не сообщает размер контекста — задайте явно
providers:
  anonymizer_proxy:
    name: anonymizer_proxy
    base_url: http://127.0.0.1:8081/v1
    model: anonymizer-proxy
    discover_models: false     # у прокси нет списка моделей — отключите автодетект
    models:
      anonymizer-proxy: {}
```

API-ключ для провайдера не нужен (на localhost прокси пускает без токена).
Реальные модель и ключ OpenRouter заданы в `.env` прокси и Hermes'ом не
видны. **Не настраивайте `fallback_model` на облачный провайдер** — иначе при
любом сбое прокси запросы молча уйдут в облако в обход анонимизации.

#### Шаг 3. Установите правила анонимизации в рабочую папку

Правила Hermes берутся **из папки проекта**: положите в корень рабочей
папки файл **`AGENTS.md`** — Hermes загружает его автоматически в каждую
сессию (приоритет: `.hermes.md` → `AGENTS.override.md` → `AGENTS.md` →
`CLAUDE.md`). Проще всего скриптом из корня установки прокси:

```powershell
Set-Location '<путь-к-прокси>'
.venv\Scripts\python.exe scripts\install_rules.py <путь-к-рабочей-папке>
```

Скрипт скопирует правила из `hermes_rules.md` (адаптация `.clinerules` под
Hermes: в нём уже есть команды office_ops) и **подставит фактический путь
установки прокси** — вручную ничего править не нужно. Опция `--clinerules`
заодно установит правила и для Cline.

> **Почему не глобальная память:** у `%LOCALAPPDATA%\hermes\memories\MEMORY.md`
> жёсткий лимит 2200 символов — правила в него целиком не помещаются и
> обрезаются. Если правила были добавлены туда раньше — удалите их из
> MEMORY.md: теперь они приходят из `AGENTS.md` рабочей папки.

> **Если прокси установлен не в `C:\Test\anonymizer_proxy`** — путь
> подставится автоматически (шаблон `hermes_rules.md` содержит путь исходной
> установки, скрипт заменяет его на ваш). Единственное требование: команда
> office_ops должна запускаться из корня установки прокси через её
> `.venv\Scripts\python.exe`.

1. Перезапустите Hermes и откройте **новый** чат.
2. Приложите `.docx`/`.xlsx` и напишите «анонимизируй приложенный файл».

#### Отличия от Cline, о которых стоит знать

- Hermes передаёт вложения ссылками `@file:…` (или файл просто упоминается
  путём в тексте сообщения) и читает файлы сам. Прокси перехватывает команду
  и подставляет текст анонимизированной копии, но дальше агент обязан работать
  только с копией и файлом результата — это предписывают правила из
  `AGENTS.md` рабочей папки (шаблон — `hermes_rules.md`; приоритет команд
  office_ops над skills).
- Режим `passthrough` (по умолчанию) не анонимирует трафик принудительно:
  если агент всё же процитирует в чате **оригинальный** документ, текст уйдёт
  в облако как есть. Для жёсткой гарантии задайте в `.env` прокси
  `ANONYMIZER_MODE=full` — тогда каждый запрос анонимируется локальной
  NER-моделью (см. «Режимы работы»).
- Де-анонимизация работает только для файлов, анонимизированных перехватом
  прокси (маппинги хранятся в его базе). Копии, созданные агентом
  самостоятельно, прокси восстановить не может — если такой инцидент
  произошёл, начните новый чат и повторите анонимизацию командой.

### Как пользоваться

Всё управление — обычными фразами в чате (Cline или Hermes Agent),
специальные команды учить не нужно:

1. **Анонимизация** — напишите «Анонимизируй приложенные файлы». Прокси
   создаст рядом с оригиналом копию `<name>.anonymized.<ext>` с плейсхолдерами
   ([PERSON_1], [ORG_2], …). В облако ничего не уходит.
2. **Проверка/правка копии** — просмотрите анонимизированную копию, которая лежит рядом с оригиналом, (структура и таблицы DOCX/XLSX сохраняются) и поправьте замену, если что-то заменилось неточно. Оригинал не изменяется.
3. **Работа с документом** — просто пишите задачу («добавь колонку в таблицы»,
   «составь резюме»): облачная модель читает и изменяет анонимизированную копию. Отдельной команды «отправить в облако» нет.
   Правки модель пишет НЕ в копию, а в отдельный файл результата, названный
   `<name>.result.<ext>` — оригинал и анонимизированная копия остаются нетронутыми.
4. **Финальная де-анонимизация** — напишите «Деанонимизируй упомянутые файлы»:
   плейсхолдеры будут заменены реальными значениями в файле результата.

Конвенцию «копия — исходник, правки — в файл результата» обеспечивает файл
правил `.clinerules`; прокси дополнительно страхует поток fallback-де-
анонимизацией. Механизм распознавания команд описан в разделе «Режимы работы».

## Архитектура

```
[Cline] → [Anonymizer Proxy] → [Облако: OpenRouter | GPTunneL | BotHub |
                ↓ ↓              | AITUNNEL | GenAPI | custom]
                ↓ ↓                     ↑
                ↓ ↘ [LM Studio]         (опционально) VPN-прокси — ТОЛЬКО
                ↓    (локальная модель,  для OpenRouter, например Happ
                ↓     генерация — опция) на 127.0.0.1:10809
      [GLiNER + Natasha/Slovnet]
       (локальная NER, in-process)
```

1. **Cline** отправляет запрос на `http://127.0.0.1:8081/v1/chat/completions` (как будто это OpenRouter)
2. **Прокси**, если в запросе содержалась анонимизация, анонимизирует его локальными NER-моделями:
   **GLiNER** (универсальный детектор PII) + **Natasha/Slovnet** (второй контур —
   русские ФИО и организации)
3. **LLM-роутер** выбирает бэкенд генерации: облако (по умолчанию) или локальная
   модель (LM Studio) — по имени модели (`local/…`, `cloud/…`,
   `<провайдер>/<модель>`, например `aitunnel/deepseek-v4-pro`), заголовку
   `X-LLM-Backend` или активному бэкенду, который переключается на лету
   командой в чате / `POST /api/backend` (см. «Конфигурация» и
   «Облачные провайдеры»)
4. **Облачный бэкенд**: прокси отправляет анонимизированный запрос выбранному
   облачному провайдеру (реестр `CLOUD_PROVIDERS` в `config.py`).
   VPN-маршрут (`OPENROUTER_PROXY` в `.env`, например `http://127.0.0.1:10809`
   или `socks5://127.0.0.1:10808`; Happ — лишь один из примеров) применяется
   **только к OpenRouter**. Российские провайдеры (GPTunneL, BotHub, AITUNNEL,
   GenAPI) и `custom` ходят **напрямую, без VPN**; при желании для
   конкретного провайдера можно задать свой `<NAME>_PROXY`. *Локальный бэкенд:
   запрос уходит в LM Studio — данные не покидают машину*
5. **Бэкенд** (облачный провайдер или локальная модель) возвращает ответ; из ответа
   локальной модели вырезается thinking-вывод
6. **Прокси** передает ответ Cline
7. **Прокси** по команде де-анонимизирует файлы результата (заменяет плейсхолдеры на реальные значения)

GLiNER и Natasha используются **только** для анонимизации (NER), не для генерации
текста. Это компактные локальные модели (GLiNER < 1.5 ГБ, веса Natasha ~29 МБ),
работающие в процессе прокси — без внешнего сервера и без генерации текста.

## Облачные провайдеры

> [!IMPORTANT]
> **Бета-тестирование.** Подключение российских провайдеров — GPTunneL, BotHub,
> AITUNNEL и GenAPI — предоставляется **в рамках бета-тестирования**.
> Базовые URL и схемы авторизации сверены с официальной документацией
> провайдеров и проверены автотестами прокси, но живые сценарии (стриминг,
> tool calling для Cline, имена моделей в каталогах) могут отличаться между
> провайдерами и их аккаунтами. Статус и параметры всех провайдеров видны в
> `GET /api/backend`. Об ошибках сообщайте разработчику прокси; 
> OpenRouter и локальная модель (LM Studio) работают в штатном (не бета) режиме.

Все облачные провайдеры работают по единому OpenAI-совместимому формату
(`POST {base_url}/chat/completions`, SSE-стриминг, tool calling) и различаются
только base URL, ключом, схемой авторизации и именами моделей.

| Провайдер                   | Base URL                                 | Ключ в .env       | Модель в .env | VPN                                           |
| ------------------------------------ | ---------------------------------------- | ---------------------- | -------------------- | --------------------------------------------- |
| **OpenRouter** (стартовый)  | `https://openrouter.ai/api/v1`         | `OPENROUTER_API_KEY` | `OPENROUTER_MODEL` | `OPENROUTER_PROXY` (опционально) |
| **GPTunneL** *(бета)*    | `https://gptunnel.ru/v1`               | `GPTUNNEL_API_KEY`   | `GPTUNNEL_MODEL`   | не нужен                               |
| **BotHub** *(бета)*      | `https://bothub.chat/api/v2/openai/v1` | `BOTHUB_API_KEY`     | `BOTHUB_MODEL`     | не нужен                               |
| **AITUNNEL** *(бета)*    | `https://api.aitunnel.ru/v1`           | `AITUNNEL_API_KEY`   | `AITUNNEL_MODEL`   | не нужен                               |
| **GenAPI** *(бета)*      | `https://proxy.gen-api.ru/v1`          | `GENAPI_API_KEY`     | `GENAPI_MODEL`     | не нужен                               |
| **custom** (свой endpoint) | `CUSTOM_BASE_URL`                      | `CUSTOM_API_KEY`     | `CUSTOM_MODEL`     | по умолчанию прямой          |

Российские провайдеры помечены «*(бета)*»: их интеграция предоставляется
в рамках бета-тестирования — при проблемах переключитесь обратно командой
«работай через облако» (или `POST /api/backend`) и сообщите об ошибке.

**Изоляция VPN:** VPN-прокси (`OPENROUTER_PROXY`, например Happ) нужен только
для доступа к OpenRouter из РФ. Российские провайдеры и `custom` ходят напрямую
(proxy=None) независимо от того, запущен ли VPN для OpenRouter; при желании
прокси включается per-provider переменной `<NAME>_PROXY`. Авторизация: у всех
провайдеров ключ передаётся как `Authorization: Bearer <ключ>`, кроме GPTunneL
(ключ без префикса Bearer — по их документации).

**Действующий облачный провайдер** — тот, кто обслуживает запросы, когда
бэкенд не «local». Правила:

- **Сразу после установки** действует OpenRouter (стартовый провайдер —
  переменная `CLOUD_PROVIDER` в `.env`); ключ при этом проверяется на старте
  и в selftest установки;
- **Явное переключение** (форма `/env-editor` или `POST /api/backend`)
  делает провайдера действующим и **запоминает** его в
  `data/runtime_state.json` — выбор переживает перезапуски;
- Переход на локальную модель память о провайдере не стирает: команда
  «работай через облако» вернёт к тому же провайдеру;
- Команды переключения на конкретных провайдеров («переключись на ботхаб»
  и т.п.) **удалены** — остались только «работай через облако» (и синонимы
  с «облаком») и «работай через локальную модель»;
- Имя модели с префиксом провайдера (`aitunnel/deepseek-v4-pro`) — разовая
  маршрутизация на провайдера с моделью из префикса; имя без префикса
  известного провайдера (`qwen/qwen-3.7-max`) работает как раньше —
  это имя модели OpenRouter-формата.

| Действие | Как |
|---|---|
| Выбрать провайдера | Форма `/env-editor` (выпадающий список) или `POST /api/backend {"backend": "gptunnel"}` |
| Вернуться в облако из local | Чат: «работай через облако» / «вернись в облако» |
| Вернуться на локальную модель | Чат: «работай через локальную модель» |
| Задать ключ/модель | Форма `/env-editor` (модель — из списка провайдера с подбором по названию) или `.env` (`<NAME>_API_KEY`, `<NAME>_MODEL`) |
| Сбросить к стартовому | Удалить `data/runtime_state.json` и перезапустить прокси |

Для `custom` укажите `CUSTOM_BASE_URL` — подойдёт любой OpenAI-совместимый
endpoint (другой агрегатор, корпоративный шлюз, self-hosted vLLM и т.п.).
Переопределение base URL/таймаута любого провайдера: `<NAME>_BASE_URL`,
`<NAME>_TIMEOUT`.

## Как это работает

### Режимы работы (ANONYMIZER_MODE)

По умолчанию работает режим **`passthrough`** (так задано в `.env.example`).
Режимы `full` и `anonymize_only` — специальные: включаются вручную в `.env`
(изменение применяется после перезапуска прокси), когда нужна другая логика.

#### `passthrough` — основной режим (по умолчанию)

Запросы к облаку идут прозрачно, анонимизация управляется двумя командами
в чате Cline:

- **«анонимизируй …»** («anonymise…») — прокси анонимизирует упомянутые файлы;
- **«деанонимизируй …»** («deanonymiz…») — прокси восстанавливает реальные
  значения в файлах результата.

Механизм: `/v1/chat/completions` сам по себе ничего не анонимизирует; прокси
распознаёт эти команды по тексту user-сообщения и перехватывает такие запросы
(сценарии ниже). Все остальные запросы проходят в облако без изменений.

Основные сценарии обработки в этом режиме:

- **Авто-анонимизация приложенных файлов**: если в ТЕКУЩЕМ
  user-сообщении (последнем содержательном сообщении диалога)
  есть команда анонимизации («анонимиз…» / «anonymis/z…»)
  и блоки `<file_content path="...">` с файлами, прокси перехватывает
  запрос: анонимизирует файлы локальной NER-моделью (создаётся копия
  `<name>.anonymized.<ext>` рядом с оригиналом, общая сессия маппингов)
  и возвращает клиенту список результатов **без обращения в облако**.
  Команда из старых сообщений истории перехват не запускает:
  последующие задачи пользователя («сравни два файла», «составь отчёт»)
  уходят в облако как обычно.
  Ответ содержит машиночитаемые маркеры `[anonymizer:done:<путь>]`,
  `[anonymizer:copy:<путь>]` и `[anonymizer:result:<путь>]` — по первому
  прокси не перехватывает повторно следующие запросы агента (защита от
  зацикливания), второй хранит путь к копии, третий — путь к файлу
  результата (куда модель пишет правки). Явное `anonymize: false`
  отключает и перехват тоже. Метаданные ответа:
  `anonymization_metadata.mode == "files_anonymization"`.
  - **Извлечение содержимого анонимизированных копий**: если в
    запросе есть блок `<file_content path="X.anonymized.*">` с заглушкой
    «Error fetching content» (клиент не умеет читать бинарные DOCX/XLSX),
    прокси сам читает локальную копию и подставляет извлечённый текст
    (markdown с таблицами) — облако получает реальное анонимизированное
    содержимое. Обычные (не анонимизированные) файлы не трогаются.
  - **Выборочная де-анонимизация ответов**: если в истории
    диалога уже есть маркер `[ANONYMIZER]`/`[anonymizer:done:...]` со
    строкой `session_id: ...` (файл ранее анонимизирован), то следующие
    запросы идут в облако как обычно, но **де-анонимизируется только
    текстовое содержимое ответа** (`message.content` / стримовые
    `delta.content`). Аргументы `tool_calls` **не трогаются** — модель
    правит анонимизированную копию плейсхолдерами. Метаданные:
    `anonymization_metadata.mode == "passthrough_deanonymized"` (поля
    `sessions`, `mappings_count`).
  - **Авто-де-анонимизация файлов**: если в user-сообщении
    есть команда «деанонимизируй…»/«deanonymiz…» и в истории есть маркеры
    `[anonymizer:result:<путь>]`, прокси де-анонимизирует **файлы результата**
    (`/api/deanonymize_file`) и возвращает подтверждение **без обращения
    в облако**. Если модель не создала файл результата, но изменила
    анонимизированную копию на месте — де-анонимизируется копия (fallback).
    Проверяется ДО анонимизации, т.к. слово «деанонимизируй» содержит
    «анонимизируй». Метаданные:
    `anonymization_metadata.mode == "files_deanonymization"`.
  - **Шпаргалка office_ops для облачной модели**: если в запросе
    есть файлы `.docx`/`.xlsx`, прокси добавляет в системный промпт
    инструкцию — не писать скрипты на python-docx/openpyxl, а вызывать
    готовые команды `python -m anonymizer_proxy.office_ops ...`
    (`list-tables`, `dump`, `read-column` — значения одной колонки
    с адресами ячеек и датами в ISO; колонка задаётся буквой, номером
    или текстом заголовка, шапка ищется в первых 20 строках журнала,
    `replace-text`, `set-cell`, `add-row`, `add-column` — вставка
    столбца на нужное место: в таблицу DOCX справа/слева от
    столбца-ориентира (`--column`/`--position`) или в лист XLSX рядом
    с целевым (ISO-даты становятся датами), в том числе `--table all`
    для правки всех таблиц одной командой, `delete-column` — удаление
    столбца XLSX/DOCX со сдвигом merge-диапазонов, `set-value`,
    `append-row`, `apply`, `insert-text` —
    вставка нового текста в конец или в середину документа). Записи результата
    атомарны; команды следует выполнять последовательно, не параллельно. Правки текста
    сохраняют форматирование, числа, даты и формулы (выполняются через
    FileParser/FileAssembler); результаты пишутся в отдельный файл
    (`--output`) либо на место исходника (`--in-place`).
    Триггер детекции клиенто-независим: блоки `<file_content path="...">`
    (Cline) или упоминание пути с `.docx`/`.xlsx` в любом тексте сообщения
    либо в аргументах `tool_calls` (агенты вроде Hermes Agent — см.
    `hermes_rules.md` для адаптации правил анонимизации под Hermes).
    В шпаргалку включён пункт о приоритете: для файлов `.anonymized.*` и
    `.result.*` правило office_ops главнее skills и штатных инструментов
    агента (xlsx, powerpoint, python-docx/openpyxl-скрипты).

При любом `ANONYMIZER_MODE` запрос может передать `anonymize: false` —
принудительный passthrough для конкретного запроса.

#### `full` — специальный режим: полная обработка каждого запроса

- Запрос → анонимизация → OpenRouter → де-анонимизация → ответ
- Используется GLiNER для NER и OpenRouter для генерации
- Канонический анонимизированный результат сохраняется в файл
  `data/anonymized_files/<session_id>/anonymized_request_*.md`, путь —
  в `anonymization_metadata.anonymized_request_file` ответа
  (для стрима — в финальном control-чанке с `anonymization_metadata`,
  который идёт до `[DONE]`)

#### `anonymize_only` — специальный режим: только анонимизация без облака

- Запрос → анонимизация локальной моделью (GLiNER NER) → сохранение
  результата в файл → ответ-заглушка. В облако ничего не отправляется,
  на этом обработка останавливается
- Системные сообщения в анонимизации не участвуют и в результат не входят —
  сохраняется только полезная часть запроса
- Анонимизированный запрос сохраняется в
  `data/anonymized_files/<session_id>/anonymized_request_*.md`,
  путь к файлу возвращается в ответе
- Позволяет посмотреть, в каком виде запрос ушёл бы в облако, и убедиться,
  что PII заменены плейсхолдерами

При любом `ANONYMIZER_MODE` запрос может передать `anonymize: false` —
принудительный passthrough для конкретного запроса.

### Канонический результат и маркеры выделения

Анонимизированный запрос имеет **единственное каноническое представление** —
markdown-рендер сообщений. Это гарантирует проверяемую цепочку
«то, что я вижу = то, что ушло в облако»:

- в **каждом режиме** канонический результат сохраняется в файл
  `data/anonymized_files/<session_id>/anonymized_request_*.md`;
- в режиме `anonymize_only` ответ (стрим и не-стрим) содержит одну служебную
  строку техсведений (режим, session_id, путь к файлу, число сущностей и
  маппингов), а затем канонический результат между маркерами:

  ```
  [Режим: anonymize_only; session_id: ...; файл: ...; сущностей: N; маппингов: M]

  <<<ANONYMIZED_RESULT>>>
  ## user
  Проверь документ от [PERSON_1]
  <<<END_ANONYMIZED_RESULT>>>
  ```

  Результат извлекается программно regex
  `<<<ANONYMIZED_RESULT>>>\n(.*?)\n<<<END_ANONYMIZED_RESULT>>>` и **идентичен**
  содержимому файла. Техинформация дублируется в `anonymization_metadata`
  (`mode`, `session_id`, `anonymized_request_file`, `entities_found`,
  `mappings_count`; для стрима — в финальном чанке SSE);
- в режиме `full` в облако уходят именно те `anonymized_messages`, из которых
  построен канонический результат: содержимое файла — проверяемая проекция
  фактически отправленного контекста.

**Архитектурная гарантия:** запрос к генерирующей модели конструирует только
прокси. Локальные NER-модели (GLiNER, Natasha) используются исключительно
для анонимизации — они возвращают список сущностей (JSON) и не формируют
никаких запросов в облако. Генерация выполняется облачной моделью
(OpenRouter или — бета — российский провайдер) либо локальной (LM Studio) —
по выбору пользователя.

### Процесс анонимизации

0. **Извлечение приложенных файлов** (все режимы):
   - Если клиент (Cline) приложил файл, но не смог его прочитать (типично для
     бинарных документов DOCX/XLSX), в тексте сообщения появляется блок
     `<file_content path="...">Error fetching content: ...</file_content>`
   - Прокси обнаруживает такие блоки, сам читает локальный файл по указанному
     пути (поддерживаются абсолютные пути, относительные от корня workspace
     и `file://` URI) и извлекает текст через `FileParser`
     (DOCX/XLSX/XML/TXT/MD)
   - Извлечённый текст подменяет заглушку-ошибку и дальше участвует в NER и
     анонимизации наравне с остальным текстом запроса
   - Если файл не найден или формат не поддерживается — блок остаётся без
     изменений, запрос не падает (в лог пишется предупреждение)
   - Извлечение через `FileParser` — **основной механизм** попадания содержимого
     офисных документов в анонимизацию: успешно прочитанные клиентом
     `<file_content>`-блоки не подменяются; маппинги общие для сессии, поэтому
     одна и та же PII получает один и тот же плейсхолдер
   - Для DOCX и XLSX `FileParser` сохраняет простейшую структуру: абзацы и
     таблицы Word, листы и ячейки Excel. Обратная сборка (`FileAssembler`,
     эндпоинт `/api/anonymize`) записывает анонимизированный текст обратно
     по координатам сегментов: сетка таблиц сохраняется, а неизменённые
     ячейки (включая формулы, числа и даты Excel) не затрагиваются
1. **NER** (Named Entity Recognition):
   - Использует локальную модель GLiNER (`knowledgator/gliner-pii-large-v1.0`) — компактный NER-энкодер, работающий в процессе прокси
   - Выявляет PII: имена, должности, организации, телефоны, email, ИНН, адреса, суммы
   - Адреса веб-сайтов (URL, `www`- и «голые» домены по белому списку TLD,
     включая кириллический `.рф`) детектируются regex-слоем в категорию
     `WEB` (`[WEB_N]`); email при этом маскируется целиком одним спаном —
     домен внутри адреса почты не дробится. При анонимизирующей сборке
     DOCX дополнительно вычищаются внешние цели гиперссылок в
     `word/_rels/*.rels` (адрес сайта не остаётся в пакете даже при
     замаскированном тексте ссылки); при де-анонимизации пакет не трогается
   - Денежные суммы распознаются и без слова валюты рядом с числом:
     сгруппированные разряды (`83 600,00`) маскируются даже тогда, когда
     валюта вынесена в заголовок колонки («Затраты, руб., без НДС»).
     Числа без группировки (почтовые индексы, годы, номера) не маскируются
   - Детерминированный вывод: при одинаковом входе и пороге модель выдаёт
     одинаковые сущности (нет «thinking»-генерации и обрезанного JSON)
   - Модель возвращает текст, тип и **символьные оффсеты** сущности; прокси
     дополнительно страхуется поиском без учёта регистра и различия ё/е
   - Для оргформ с названием в кавычках (`ООО «ИРИС»`) прокси дополнительно
     выделяет ядро (`ИРИС`) и заменяет также все короткие вхождения названия
     — разрозненные упоминания одной компании не утекают в облако
   - Поиск сущностей устойчив к написанию: регистр, ё/е и визуально одинаковые
     буквы кириллицы/латиницы (`«1С»`/`«1C»`) считаются совпадением —
     значение, возвращённое моделью в одном алфавите, покрывает вхождения
     в другом
   - Категории задаются списком меток в вызове модели (маппинг на
     PERSON/ORG/LOC/…); качество детекции зависит от модели и порога
     `NER_THRESHOLD`
   - Текст длиннее лимита модели (окно 768 токенов, чанк ~1500 символов — NER_MAX_INPUT_CHARS) автоматически режется на чанки
     с перекрытием; сущности переносятся в координаты исходного текста
   - Если модель не загрузилась или упала, NER-детекция считается
     **невыполненной**: при анонимизации файла прокси возвращает явную ошибку,
     а не молча «0 сущностей» — файл не будет выглядеть анонимизированным,
     когда это не так
   - Детерминированная страховка: оргформы (ООО/АО/ПАО/ОАО/ЗАО/НКО/НПФ/ГК,
     Фонд/Банк + название) ловятся regex с учётом регистра даже если модель
     их пропустила
2. **Замена**:
   - PII заменяется плейсхолдерами вида `[Имя_1]`, `[Организация_1]`, `[Телефон_1]`
   - Если значение признано PII хотя бы один раз, заменяются **все** его
     точные вхождения в тексте (LLM часто пропускает повторные упоминания);
     одно и то же значение всегда получает один и тот же плейсхолдер
   - Маппинги сохраняются в SQLite (`anonymizer.db`) с TTL 24 часа
3. **Отправка в облако**:
   - Анонимизированный запрос отправляется в OpenRouter
   - Модель генерирует ответ (без знания реальных данных)
4. **Де-анонимизация**:
   - Ответ от OpenRouter проходит обратную замену плейсхолдеров на реальные значения
   - Возвращается клиенту

### Хранение данных

- **БД**: `anonymizer.db` (SQLite) — маппинги, логи
- **Логи**: `data/logs/` — JSON-логи запросов/ответов
- **Анонимизированные файлы**: `data/anonymized_files/`
- **Маппинги**: `data/mappings/` — временные файлы с TTL

## Конфигурация (.env)

> Файл `.env` создаётся автоматически при установке (см. «Быстрый старт»);
> этот раздел — справочник параметров для ручной настройки. Изменения
> применяются после перезапуска прокси. Файл `.env` и каталог `data/`
> (содержит PII!) исключены из git через `.gitignore`.

### Редактор настроек из браузера

Править `.env` можно и без текстового редактора — через экранную форму:
**http://127.0.0.1:8081/env-editor** (если задан `PROXY_API_TOKEN`, он
вводится в форму один раз за сессию; на localhost без токена форма работает
сразу). Ярлык запуска прокси (меню Пуск Windows / `Anonymizer Proxy.app`
на macOS) открывает эту форму автоматически; при уже работающем прокси
повторный клик по ярлыку просто снова открывает её.

- Карточка **«Облачный провайдер»**: выбор провайдера выпадающим списком —
  выбранный сразу становится **действующим** (запоминается в
  `runtime_state.json`, без перезапуска); ключ показывается маской
  (`sk-…7890`) с меткой «задан / не задан» и полем для ввода нового
  значения; модель — выпадающий список с подбором по частично введённому
  названию (источник — `/models` провайдера; для OpenRouter и GenAPI
  публичный, у остальных — по ключу; если список недоступен, модель
  вводится вручную). Выбранные модель и ключ сохраняются перманентно в
  `.env` и применяются к работающему прокси без перезапуска;
- редактируются только ключи из **белого списка** (облачные провайдеры,
  LM Studio, host/port прокси); произвольные переменные через форму записать
  нельзя; настройки `PROXY_*` и `LOCAL_LLM_*` применяются после перезапуска;
- перед каждой записью создаётся бэкап в `data/env_backups/`
  (хранятся последние 10 копий); формат файла (UTF-8, BOM, CRLF/LF)
  сохраняется, комментарии и порядок строк не трогаются;
- кнопка «Сохранить и перезапустить» перезапускает прокси (20–40 сек —
  загружается NER-модель) — нужна для настроек host/port и LM Studio.

API формы: `GET /api/env/schema` (состояние ключей, секреты — маской),
`POST /api/env` (`{"updates": {KEY: "значение" | null}}`), `GET /api/models`
(список моделей провайдера), `POST /api/restart`.


```ini
# OpenRouter API ключ (получить на https://openrouter.ai/keys)
OPENROUTER_API_KEY=sk-or-v1-...

# Модель в OpenRouter (должна существовать в OpenRouter)
OPENROUTER_MODEL=qwen/qwen3.7-plus

# Дефолтный облачный провайдер: openrouter (по умолчанию) | gptunnel | bothub
# | aitunnel | genapi | custom. Российские провайдеры работают без VPN
# (бета-тестирование) — полная таблица в разделе «Облачные провайдеры»:
#   GPTunneL:  GPTUNNEL_API_KEY / GPTUNNEL_MODEL
#   BotHub:    BOTHUB_API_KEY / BOTHUB_MODEL
#   AITUNNEL:  AITUNNEL_API_KEY / AITUNNEL_MODEL
#   GenAPI:    GENAPI_API_KEY / GENAPI_MODEL
#   Свой OpenAI-совместимый endpoint: CUSTOM_BASE_URL / CUSTOM_API_KEY / CUSTOM_MODEL
# CLOUD_PROVIDER=openrouter

# NER-движок (GLiNER) — локальная анонимизация
# Модель с HuggingFace (при первом запуске скачивается в кэш, дальше офлайн)
NER_MODEL=knowledgator/gliner-pii-large-v1.0
# Порог уверенности для сущностей (0.0–1.0). 0.3 — для redaction важнее
# полнота: «Фамилия И.О.» модель даёт со скором ~0.4
NER_THRESHOLD=0.3
# Второй контур — Natasha/Slovnet (русские ФИО и организации).
# Отключить: NER_NATASHA=0. Веса ~29 МБ скачиваются один раз в data/models
NER_NATASHA=1
# Бэкенд инференса: auto|onnx — ONNX Runtime с автовыбором провайдера
# (CUDA → DirectML → CPU); torch — PyTorch (аварийный фоллбек)
NER_BACKEND=auto
# Устройство для PyTorch-фоллбэка: cpu (по умолчанию) или directml
NER_DEVICE=cpu
# Максимальный размер чанка (символы) на один вызов модели.
# Окно модели — 768 токенов (~2.4 симв./токен для русского): 1500 символов
# гарантируют отсутствие тихого усечения хвоста чанка; длиннее — чанки
NER_MAX_INPUT_CHARS=1500
# Перекрытие соседних чанков (символы): защищает сущности на границах чанков
NER_CHUNK_OVERLAP_CHARS=200
# Таймаут NER-вызова в секундах (страховочный)
NER_TIMEOUT_SECONDS=300

# VPN-прокси для доступа к OpenRouter, если он недоступен напрямую.
# Пример — Happ; подойдёт любой HTTP/SOCKS5-прокси. Без VPN оставьте пустым:
# применяется ТОЛЬКО к OpenRouter — российские провайдеры (бета) ходят напрямую.
OPENROUTER_PROXY=
# пример заполненного значения: http://127.0.0.1:10809

# Настройки прокси
# По умолчанию сервер слушает ТОЛЬКО localhost (127.0.0.1).
# Для 0.0.0.0 ОБЯЗАТЕЛЬНО задайте PROXY_API_TOKEN — иначе сервер не запустится.
PROXY_HOST=127.0.0.1
PROXY_PORT=8081

# Токен доступа к административным /api/* эндпоинтам (логи, де-анонимизация,
# экспорт, статус, cleanup). Передаётся заголовком:
#   Authorization: Bearer <token>   или   X-API-Key: <token>
# Генерация: python -c "import secrets; print(secrets.token_urlsafe(32))"
PROXY_API_TOKEN=<сгенерируйте случайный токен>

# Режим работы: full, anonymize_only или passthrough
# full - полная обработка: анонимизация → облако → де-анонимизация
# anonymize_only - только анонимизация без отправки в облако (возвращает фиктивный ответ)
# passthrough - явное управление: запросы клиентов (Cline, Hermes Agent и др.)
#   идут без анонимизации, команда «анонимизируй файл» перехватывается (основной)
ANONYMIZER_MODE=passthrough

# Keep-alive во время подготовки (NER): прокси периодически отдаёт клиенту
# нейтральные SSE-комментарии, пока идёт анонимизация, чтобы клиент не считал
# запрос зависшим. Отключить: KEEPALIVE_ENABLED=false.
KEEPALIVE_ENABLED=true
KEEPALIVE_INTERVAL_SECONDS=3

# Уровень логирования: DEBUG, INFO, WARNING, ERROR
LOG_LEVEL=INFO

# Исключаем localhost из VPN
NO_PROXY=localhost,127.0.0.1,::1
```

**Важно**: прокси использует **только** эти настройки. Параметры из Cline (модель, API-ключ) **игнорируются**. Cline просто отправляет запрос на `http://127.0.0.1:8081/v1/chat/completions`, а прокси подставляет свои реальные значения из `.env`.

## office_ops — правка документов командами

CLI-инструментарий `anonymizer_proxy/office_ops.py`: облачная модель вызывает
готовые команды вместо написания скриптов на python-docx/openpyxl. Прокси сам
добавляет эту шпаргалку в системный промпт, когда в запросе есть файлы
`.docx`/`.xlsx`. Запуск (из корня проекта, через venv):

```powershell
.venv\Scripts\python.exe -m anonymizer_proxy.office_ops <команда> [параметры]
```

### Общие правила

- Результат пишется в `--output ПУТЬ` либо на место исходника `--in-place`;
  без одного из них команда завершается с ошибкой. По умолчанию исходник
  не трогается.
- Запись атомарная (через временный файл): прерванный запуск не оставит
  «половинный» документ. Команды выполнять последовательно, не параллельно.
- Замены текста (`replace-text`, `apply`) идут через FileParser/FileAssembler:
  сохраняются форматирование, стили, числа, даты и формулы — перезаписываются
  только изменённые сегменты.

### Чтение

| Команда                                                               | Назначение                                                                                                                                                                                                                                                                                                                                                                                                            |
| ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `list-tables --file F`                                                     | Структура: таблицы DOCX (размер, заголовок 1-й строки) или листы XLSX                                                                                                                                                                                                                                                                                                             |

## NER-движки (GLiNER + Natasha/Slovnet)

Локальные модели выполняют NER (анонимизацию) в процессе прокси.
GLiNER — основной контур: инференс идёт через **ONNX Runtime с автодетекцией
железа** — код одинаков на любой машине, ускорение появляется автоматически
при наличии GPU. Natasha/Slovnet — второй контур для русских ФИО и организаций
(подробнее ниже).

1. **Зависимости**: `pip install -r requirements.txt` — пакеты `gliner`
   (тянет `torch`, CPU-сборка ~2 ГБ при установке) и `onnxruntime`.
   Для GPU-ускорения замените пакет `onnxruntime` на **ровно один** из:

   - `onnxruntime-directml` — Windows, любые GPU (включая AMD/Intel) и NPU;
   - `onnxruntime-gpu` — NVIDIA CUDA. На Windows CUDA-стек ставится
     полностью через pip (без системного CUDA Toolkit):

     ```powershell
     pip uninstall onnxruntime
     pip install onnxruntime-gpu==1.24.4 nvidia-cublas-cu12 nvidia-cudnn-cu12 nvidia-cufft-cu12 nvidia-cuda-runtime-cu12
     ```

     **Пин 1.24.4 обязателен**: версии 1.25+ собраны под CUDA 13, DLL
     которого не распространяются через pip. Прокси сам находит
     pip-установленные CUDA-DLL (регистрирует их каталоги при загрузке).
     Код при этом не меняется: провайдер подбирается автоматически
     (CUDA → DirectML → CPU). При установке GPU-пакета сначала удалите
     базовый: `pip uninstall onnxruntime`.
2. **Модель**: `NER_MODEL` в `.env` — идентификатор модели на HuggingFace
   (по умолчанию `knowledgator/gliner-pii-large-v1.0`; ONNX-веси
   `onnx/model.onnx` входят в репозиторий модели). При первом запуске веса
   скачиваются в кэш (`~/.cache/huggingface`), дальше работа офлайн. Если
   прямого доступа к huggingface.co нет — загрузите веса через VPN-прокси
   (`HTTPS_PROXY=http://127.0.0.1:10809`).
3. **Бэкенд**: `NER_BACKEND` — `auto|onnx` (по умолчанию; ONNX Runtime с
   автовыбором провайдера) или `torch` (PyTorch, аварийный путь). Если ONNX
   не загрузился, движок видимо откатывается на PyTorch (WARNING в лог).
   Фактический бэкенд и версия прокси показываются в `/health` и `/api/status`
   (`ner_backend`).
   **Локальная LLM через LM Studio** (для сценариев, где данные не должны
   покидать машину — например, модель должна работать с конфиденциальными
   суммами в Excel): запустите LM Studio, загрузите модель и заполните в
   `.env` `LOCAL_LLM_BASE_URL` / `LOCAL_LLM_MODEL`, затем перезапустите
   прокси. Переключение бэкендов — **без перезапуска прокси**, тремя
   способами: команда в чате («работай через локальную модель» /
   «работай через облако»), `POST /api/backend {"backend": "local"}`
   (`GET /api/backend` — текущий статус) или имя модели в Cline с префиксом
   `local/`. На локальном бэкенде авто-анонимизация приложенных файлов
   отключена (данные не покидают машину); thinking-вывод модели
   (`<think>…</think>`, `reasoning_content`) вырезается из ответов.
   Там же, в чате, работает команда **«перезапусти прокси»**: сервер
   корректно завершится и поднимется заново через `.venv` (лог —
   `data/logs/restart.log`); полезно после правок кода или `.env`.

   Параметры `.env` для локальной модели:

   | Параметр             | По умолчанию      | Описание                                                                                                                                                                                                                                                                                    |
   | ---------------------------- | ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | `LOCAL_LLM_BASE_URL`       | `http://127.0.0.1:1234/v1` | Адрес OpenAI-совместимого сервера LM Studio                                                                                                                                                                                                                                 |
   | `LOCAL_LLM_MODEL`          | *(пусто)*             | Имя модели в LM Studio; если пусто — берётся первая загруженная не-embedding модель. Запросы с этим именем (или с префиксом`local/`) маршрутизируются локально                         |
   | `LOCAL_LLM_TIMEOUT`        | `600`                      | Таймаут запроса к локальной модели, сек (thinking-модели отвечают медленно)                                                                                                                                                                  |
   | `LOCAL_LLM_MIN_MAX_TOKENS` | `16384`                    | Минимальный бюджет выходных токенов: поднимает слишком маленький`max_tokens` клиента (иначе thinking съедает лимит и ответ обрывается на полуслове). `0` — не поднимать |
   | `LOCAL_LLM_API_KEY`        | `lm-studio`                | Ключ авторизации LM Studio (обычно не требуется)                                                                                                                                                                                                                    |

   Все параметры необязательны; меняются они только в `.env` и требуют
   перезапуска прокси. Само переключение бэкендов — без перезапуска.
4. **Порог**: `NER_THRESHOLD` (по умолчанию 0.3) отсекает слабоуверенные
   сущности: выше — меньше ложных срабатываний, ниже — выше recall. Для
   redaction-задач полнота важнее точности: русские «Фамилия И.О.» в подписях
   документов GLiNER даёт со скором ~0.4, и при старом пороге 0.5 они
   терялись (реальная утечка — см. историю изменений).
5. **Чанкование**: окно модели 768 токенов (~2.4 симв./токен для русского);
   `NER_MAX_INPUT_CHARS` (по умолчанию 1500) держит чанк внутри окна —
   хвосты чанков не усекаются молча. Соседние чанки перекрываются на
   `NER_CHUNK_OVERLAP_CHARS` (по умолчанию 200), чтобы сущности на границе
   не терялись. Прогресс пишется в лог («NER: чанк i/N»), длинные
   документы видны в консоли прокси.
6. **Таймаут**: `NER_TIMEOUT_SECONDS` (по умолчанию 300 с) прерывает
   зависший инференс (ошибка уходит клиенту, а не висит вечно).
7. **Кэш**: результаты NER кэшируются по хэшу текста в памяти процесса —
   повторная анонимизация того же файла (новый чат, повторная команда)
   выполняется мгновенно, без повторного инференса. Сбрасывается
   перезапуском прокси.
8. **Детектирование чат-команд** (`COMMAND_CLASSIFIER`): гибридная схема —
   regex-префильтр и точные правила (включая деструктивный «перезапусти
   прокси») работают всегда; дополнительный GLiNER zero-shot-слой для
   свободных формулировок команд включается значением `auto` (по умолчанию
   `off`: zero-shot-скоры не калиброваны и зависят от формулировок —
   проверено живыми тестами). Пороги: `COMMAND_CLASSIFIER_THRESHOLD`
   (позитивы дают 0.05–0.23), `COMMAND_CLASSIFIER_MARGIN` (отрыв лучшей
   метки от второй), таймаут — `COMMAND_CLASSIFIER_TIMEOUT`.

### Второй контур: Natasha/Slovnet (русские ФИО и организации)

GLiNER-PII обучен в основном на английском, поэтому русские персональные
данные — слабое место: «Фамилия И.О.» в подписях документов получает скор
ниже порога, склонённые формы («Вдовину А.С.») не распознаются вовсе.
Поэтому рядом с GLiNER работает **второй специализированный контур** —
Natasha/Slovnet (`anonymizer/natasha_engine.py`):

- **Slovnet NER** (`NewsNERTagger`) — русский NER, F1 PER ≈ 0.97 на
  Collection5/factRuEval-2016; маппинг PER → PERSON, ORG → ORG, LOC → LOC;
- **NamesExtractor** (yargy + pymorphy2) — детерминированное извлечение
  русских ФИО по грамматикам: полные имена, «Фамилия И.О.», «И.О. Фамилия»,
  любые падежные формы.

Результаты всех трёх слоёв (regex + GLiNER + Natasha) объединяются по
оффсетам: приоритет у более длинных точных спанов; LLM-спан не может
«поглотить» несколько точных сущностей (иначе из документа исчезали слова
между ФИО). Спаны обрезаются по переводу строки, чтобы служебные слова
(«Тел.», «Исполнитель») не попадали под замену.

Настройки:

- `NER_NATASHA=1|0` (по умолчанию 1) — включение/отключение контура;
- веса компактны (~29 МБ: Slovnet NER 2 МБ + Navec 25 МБ), скачиваются
  один раз при первом запуске в `data/models/`, дальше офлайн;
- инференс только на NumPy/CPU, без torch; сбой Natasha не останавливает
  анонимизацию — остаются GLiNER + regex (WARNING в логе);
- для pymorphy2 нужен `pkg_resources`: в `requirements.txt` закреплён
  `setuptools>=75,<81` (в setuptools 81+ пакет удалён, а в Python 3.12+
  setuptools больше не входит в комплект).

Отключить второй контур целиком: `NER_NATASHA=0` в `.env`.

## Что нужно помнить

1. **Модель в .env** должна точно совпадать с существующей в OpenRouter (например, `qwen/qwen3.7-plus`).
2. **VPN-прокси** нужен, только если OpenRouter недоступен напрямую: задаётся
   параметром `OPENROUTER_PROXY` в `.env` (например, Happ на `127.0.0.1:10809`).
3. **NER-модели** (GLiNER + Natasha/Slovnet) загружаются автоматически при
   старте прокси; порог, чанкование и второй контур задаются в `.env`
   (см. раздел «NER-движки (GLiNER + Natasha/Slovnet)»).
4. **Cline** настраивается на `http://127.0.0.1:8081/v1` и игнорирует реальные модели/ключи.
5. **Логи** помогают отлаживать проблемы (print + файлы).
6. **Изменения в `.env`** (включая `ANONYMIZER_MODE`) применяются только после
   перезапуска прокси. Если поведение не изменилось — проверьте, что старый
   процесс остановлен, а новый запущен (эндпоинт `/health` показывает текущий режим).

## Диагностика

- **HTTP 500** — неправильное имя модели: проверьте `OPENROUTER_MODEL` в `.env`
  (модель должна существовать в OpenRouter, например `qwen/qwen3.7-plus`).
- **HTTP 403 «Access denied»** — OpenRouter требует доступ через VPN: задайте
  `OPENROUTER_PROXY` в `.env` (например, `http://127.0.0.1:10809` для Happ);
  если VPN-прокси стал не нужен — наоборот, очистите значение.
- **HTTP 401 «User not found»** — неверный `OPENROUTER_API_KEY` в `.env`:
  ключ не существует, удалён или остался плейсхолдером после установки.
  Вставьте действующий ключ с https://openrouter.ai/keys и перезапустите
  прокси. Локальная анонимизация при этом работает.
- **Локальный бэкенд: ошибка соединения с `127.0.0.1:1234`** — LM Studio не
  запущен или модель не загружена: запустите LM Studio, загрузите модель
  (`LOCAL_LLM_MODEL` в `.env`) и переключитесь обратно командой
  «работай через локальную модель». На время можно вернуться в облако:
  «работай через облако» или `POST /api/backend {"backend": "openrouter"}`.
- **«NER-модель не загрузилась»** — проверьте, что пакет `gliner` установлен и
  веса модели скачаны (`NER_MODEL` в `.env`; при первом запуске нужен доступ к
  huggingface.co). Без NER анонимизация файлов/запросов вернёт ошибку
  (NERUnavailableError), а не ограниченный regex-результат.
- **«NER-модель не загрузилась» при работающем `.venv`** — прокси запущен НЕ тем
  интерпретатором. Пакет `gliner` установлен только в виртуальном окружении
  `.venv`; запуск глобальным `python.exe` (например, `C:\Python314\python.exe`)
  даёт мгновенный `ModuleNotFoundError: gliner`, и все файлы получают ошибку
  анонимизации за доли секунды. Признак: в логе старта строка
  «Интерпретатор: …» указывает не на `.venv\Scripts\python.exe` (Windows) или
  `.venv/bin/python` (macOS/Linux). Запускайте прокси скриптом
  `start_proxy.cmd` (Windows) или `./start_proxy.sh` (macOS/Linux) из корня
  проекта — они гарантированно используют `.venv`.
- **«Natasha: скачивание …» падает с HTTPError / сетевой ошибкой** — первый
  запуск Natasha-контура качает веса (~29 МБ) с `storage.yandexcloud.net`
  в `data/models/`. Без интернета положите файлы
  `navec_news_v1_1B_250K_300d_100q.tar` и `slovnet_ner_news_v1.tar` туда
  вручную или отключите контур: `NER_NATASHA=0` (анонимизация продолжит
  работать на GLiNER + regex).
- **«pkg_resources is deprecated» / ModuleNotFoundError: pkg_resources** —
  для pymorphy2 (Natasha) нужен `setuptools<81`; версия закреплена в
  `requirements.txt`.

## Термины

Основные аббревиатуры и названия, встречающиеся в этом документе.

### Анонимизация и NER

| Термин                                | Расшифровка / значение                                                                                                                                                                                                       |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **NER**                               | Named Entity Recognition — «распознавание именованных сущностей»: локальная модель находит в тексте имена, организации, телефоны, суммы и т.п. |
| **PII**                               | Personally Identifiable Information — персональные данные, позволяющие идентифицировать человека (ФИО, телефоны, ИНН, адреса…)                                       |
| **GLiNER**                            | Компактная локальная NER-модель (zero-shot: находит сущности по текстовым меткам-описаниям без дообучения) — основной контур детекции     |
| **Natasha / Slovnet / Navec / yargy** | Библиотеки второго контура детекции, заточенные под русский язык: русские ФИО и организации (веса ~29 МБ, работают на CPU)                        |
| **Плейсхолдер**            | Замена реального значения в тексте:`[PERSON_1]`, `[ORG_2]`, `[PHONE_3]`. Обратная замена — де-анонимизация                                                                     |
| **Сущность / оффсеты** | Найденный фрагмент текста; оффсеты — символьные координаты начала/конца фрагмента (нужны для точной замены)                                          |
| **regex**                             | Regular expression — регулярное выражение: шаблон поиска текста (используется как детерминированная страховка детекции)                                  |

### Модели и инференс

| Термин                  | Расшифровка / значение                                                                                                                                                                                                           |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **LLM**                 | Large Language Model — большая языковая модель (генерирует текст)                                                                                                                                              |
| **LLM-роутер**    | Механизм прокси, выбирающий бэкенд генерации: облако или локальная модель                                                                                                            |
| **Бэкенд**        | Здесь: источник генерации — облачный провайдер (OpenRouter или российский из списка — бета) или LM Studio (локально)                                                   |
| **LM Studio**           | Приложение, поднимающее локальную OpenAI-совместимую модель на`127.0.0.1:1234/v1`                                                                                                                |
| **thinking-вывод** | Служебные «размышления» модели (блок «think» и поле`reasoning_content`); из ответов локальной модели вырезаются, чтобы Cline получал чистый текст |
| **ONNX / ONNX Runtime** | Формат и движок инференса NER-модели; провайдеры: CUDA → DirectML → CPU (выбираются автоматически)                                                                                   |
| **CUDA**                | Ускорение NVIDIA GPU (стек ставится через pip, без системного CUDA Toolkit)                                                                                                                                  |
| **DirectML**            | Ускорение AMD/Intel GPU и NPU на Windows (через DirectX 12)                                                                                                                                                                        |
| **MPS**                 | Metal Performance Shaders — ускорение на GPU Apple Silicon (macOS M1–M4)                                                                                                                                                               |
| **zero-shot**           | Классификация без дообучения модели под задачу (в проекте — опциональный слой детектора команд, по умолчанию выключен)                          |

### Клиенты, сервисы и протоколы

| Термин                                  | Расшифровка / значение                                                                                                                                                                                                                                                                                                                                                                                              |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **API**                                 | Application Programming Interface — программный интерфейс (эндпоинты`/api/*`)                                                                                                                                                                                                                                                                                                                          |
| **OpenAI-совместимый**       | Формат запросов/ответов`POST /v1/chat/completions` — стандарт де-факто, на него рассчитаны клиенты                                                                                                                                                                                                                                                                       |
| **OpenRouter**                          | Агрегатор облачных LLM (openrouter.ai); доступ через API-ключ                                                                                                                                                                                                                                                                                                                                          |
| **Облачный провайдер** | OpenAI-совместимый сервис генерации из реестра прокси: OpenRouter, GPTunneL, BotHub, AITUNNEL, GenAPI или свободно настраиваемый endpoint (`custom`); **действующий** провайдер — последний явно выбранный (форма `/env-editor`, `POST /api/backend`; персист в `runtime_state.json`), сразу после установки — OpenRouter (`CLOUD_PROVIDER`). Российские провайдеры — в статусе бета-тестирования |
| **Cline**                               | AI-ассистент — расширение VS Code; основной клиент прокси                                                                                                                                                                                                                                                                                                                                      |
| **Hermes Agent**                        | AI-ассистент (Nous Research), работает с прокси как с OpenAI-совместимым endpoint                                                                                                                                                                                                                                                                                                               |
| **SSE / стриминг**              | Server-Sent Events — потоковая передача ответа частями (delta-чанками)                                                                                                                                                                                                                                                                                                                           |
| **keep-alive**                          | Нейтральные SSE-комментарии в стриме, чтобы клиент не считал запрос зависшим во время NER                                                                                                                                                                                                                                                                         |
| **tool-calling**                        | Вызов «инструментов» агентом (Cline) — аргументы пробрасываются через прокси без анонимизации                                                                                                                                                                                                                                                              |
| **VPN-прокси**                    | Промежуточный HTTP/SOCKS5-сервер (например, Happ) для доступа к OpenRouter из РФ                                                                                                                                                                                                                                                                                                             |

### Инфраструктура и окружение

| Термин                | Расшифровка / значение                                                                                                                                                        |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **venv / .venv**      | Виртуальное окружение Python — изолированные зависимости проекта (запускать прокси строго через него)          |
| **uv**                | Быстрый менеджер Python и зависимостей; ставит Python, создаёт окружение по`uv.lock`                                                       |
| **FastAPI / Uvicorn** | Web-фреймворк и ASGI-сервер, на которых работает прокси                                                                                                   |
| **Pydantic**          | Библиотека схем/валидации запросов и ответов                                                                                                              |
| **HuggingFace**       | Хранилище моделей (huggingface.co) — оттуда скачиваются веса GLiNER                                                                                        |
| **SQLite**            | Встраиваемая БД (`data/anonymizer.db`) — маппинги и логи                                                                                                           |
| **TTL**               | Time To Live — срок жизни маппингов (24 часа, потом автоочистка)                                                                                          |
| **fallback**          | Резервный путь: ONNX → PyTorch, де-анонимизация копии → файла результата                                                                        |
| **MotW**              | Mark of the Web — метка Windows «скачано из интернета», блокирующая неподписанные скрипты (снимается установщиком) |
| **ExecutionPolicy**   | Политика выполнения PowerShell-скриптов; установщик использует`-ExecutionPolicy Bypass`                                                          |
| **preflight**         | Предварительная проверка системных требований установщиком (ОС, ОЗУ, диск)                                                        |
