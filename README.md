# Anonymizer Proxy — Резюме проекта

## Что это такое

**Anonymizer Proxy** — это локальный прокси-сервер на FastAPI, который сидит между клиентом (Cline) и облачными LLM (OpenRouter). Его задача — анонимизировать запросы (NER + плейсхолдеры), отправлять их в облако, получать ответы и де-анонимизировать их обратно.

Помимо прозрачной автоматической анонимизации, прокси поддерживает **ручное
управление**: пользователь может (1) отправить промпт сразу без анонимизации,
(2) анонимизировать и просмотреть/отредактировать результат, (3) отправить
отредактированный анонимизированный промпт; при работе с файлами модель правит
анонимизированную копию, а де-анонимизация выполняется только в самом конце.

Это позволяет использовать облачные LLM (например, Qwen) без раскрытия
чувствительных данных (PII) третьим лицам.

## Архитектура

```
[Cline] → [Anonymizer Proxy] → [OpenRouter]
                ↓
           [LM Studio] (локальная NER)
                ↓
         [Happ VPN] (для OpenRouter)
```

1. **Cline** отправляет запрос на `http://127.0.0.1:8081/v1/chat/completions` (как будто это OpenRouter)
2. **Прокси** принимает запрос, анонимизирует его с помощью локальной NER-модели (LM Studio)
3. **Прокси** отправляет анонимизированный запрос в **OpenRouter** через **Happ VPN** (прокси на `127.0.0.1:10809`)
4. **OpenRouter** возвращает ответ
5. **Прокси** де-анонимизирует ответ (заменяет плейсхолдеры на реальные значения)
6. **Прокси** возвращает ответ Cline

LM Studio используется **только** для анонимизации (NER), не для генерации текста.

## Как это работает

### Режимы работы (ANONYMIZER_MODE)

1. **`full`** (по умолчанию) — полная обработка:
   - Запрос → анонимизация → OpenRouter → де-анонимизация → ответ
   - Используется LM Studio для NER и OpenRouter для генерации
   - Канонический анонимизированный результат сохраняется в файл
     `data/anonymized_files/<session_id>/anonymized_request_*.md`, путь —
     в `anonymization_metadata.anonymized_request_file` ответа
     (для стрима — в финальном control-чанке с `anonymization_metadata`,
     который идёт до `[DONE]`)

2. **`anonymize_only`** — только анонимизация, без облака (проверка конфиденциальности):
   - Запрос → анонимизация локальной моделью (LM Studio NER) → сохранение
     результата в файл → ответ-заглушка. В облако ничего не отправляется,
     на этом обработка останавливается
   - Системные сообщения в анонимизации не участвуют и в результат не входят —
     сохраняется только полезная часть запроса
   - Анонимизированный запрос сохраняется в
     `data/anonymized_files/<session_id>/anonymized_request_*.md`,
     путь к файлу возвращается в ответе
   - Позволяет посмотреть, в каком виде запрос ушёл бы в облако, и убедиться,
     что PII заменены плейсхолдерами

3. **`passthrough`** (основной для явной схемы) — запросы идут без анонимизации:
   - `/v1/chat/completions` не анонимизирует и не де-анонимизирует
     (прозрачный прокси); вся анонимизация — через явные вызовы `/api/*`
   - Cline работает в обычном режиме, инструменты плагина управляют
     анонимизацией шаг за шагом
   - **Исключение — авто-анонимизация приложенных файлов**: если в запросе
     есть команда анонимизации («анонимиз…» / «anonymis/z…» в user-сообщении)
     и блоки `<file_content path="...">` с файлами, прокси перехватывает
     запрос: анонимизирует файлы локальной NER-моделью (создаётся копия
     `<name>.anonymized.<ext>` рядом с оригиналом, общая сессия маппингов)
     и возвращает клиенту список результатов **без обращения в облако**.
     Ответ содержит машиночитаемые маркеры `[anonymizer:done:<путь>]`,
     `[anonymizer:copy:<путь>]` и `[anonymizer:result:<путь>]` — по первому
     прокси не перехватывает повторно следующие запросы агента (защита от
     зацикливания), второй хранит путь к копии, третий — путь к файлу
     результата (куда модель пишет правки). Явное `anonymize: false`
     отключает и перехват тоже. Метаданные ответа:
     `anonymization_metadata.mode == "files_anonymization"`.
   - **Исключение — извлечение содержимого анонимизированных копий**: если в
     запросе есть блок `<file_content path="X.anonymized.*">` с заглушкой
     «Error fetching content» (клиент не умеет читать бинарные DOCX/XLSX),
     прокси сам читает локальную копию и подставляет извлечённый текст
     (markdown с таблицами) — облако получает реальное анонимизированное
     содержимое. Обычные (не анонимизированные) файлы не трогаются.
   - **Исключение — выборочная де-анонимизация ответов**: если в истории
     диалога уже есть маркер `[ANONYMIZER]`/`[anonymizer:done:...]` со
     строкой `session_id: ...` (файл ранее анонимизирован), то следующие
     запросы идут в облако как обычно, но **де-анонимизируется только
     текстовое содержимое ответа** (`message.content` / стримовые
     `delta.content`). Аргументы `tool_calls` **не трогаются** — модель
     правит анонимизированную копию плейсхолдерами. Метаданные:
     `anonymization_metadata.mode == "passthrough_deanonymized"` (поля
     `sessions`, `mappings_count`).
   - **Исключение — авто-де-анонимизация файлов**: если в user-сообщении
     есть команда «деанонимизируй…»/«deanonymiz…» и в истории есть маркеры
     `[anonymizer:result:<путь>]`, прокси де-анонимизирует **файлы результата**
     (`/api/deanonymize_file`) и возвращает подтверждение **без обращения
     в облако**. Если модель не создала файл результата, но изменила
     анонимизированную копию на месте — де-анонимизируется копия (fallback).
     Проверяется ДО анонимизации, т.к. слово «деанонимизируй» содержит
     «анонимизируй». Метаданные:
     `anonymization_metadata.mode == "files_deanonymization"`.

При любом `ANONYMIZER_MODE` запрос может передать `anonymize: false` —
принудительный passthrough для конкретного запроса.

### Канонический результат и маркеры выделения

Анонимизированный запрос имеет **единственное каноническое представление** —
markdown-рендер сообщений. Это гарантирует проверяемую цепочку
«то, что я вижу = то, что ушло в облако»:

- в **каждом режиме** канонический результат сохраняется в файл
  `data/anonymized_files/<session_id>/anonymized_request_*.md`;
- в режиме `anonymize_only` ответ (стрим и не-стрим) содержит одну служебную
  строку техсведений (режим, session_id, путь к файлу, число сущностей и
  маппингов), а затем канонический результат между маркерами:

  ```
  [Режим: anonymize_only; session_id: ...; файл: ...; сущностей: N; маппингов: M]

  <<<ANONYMIZED_RESULT>>>
  ## user
  Проверь документ от [PERSON_1]
  <<<END_ANONYMIZED_RESULT>>>
  ```

  Результат извлекается программно regex
  `<<<ANONYMIZED_RESULT>>>\n(.*?)\n<<<END_ANONYMIZED_RESULT>>>` и **идентичен**
  содержимому файла. Техинформация дублируется в `anonymization_metadata`
  (`mode`, `session_id`, `anonymized_request_file`, `entities_found`,
  `mappings_count`; для стрима — в финальном чанке SSE);
- в режиме `full` в облако уходят именно те `anonymized_messages`, из которых
  построен канонический результат: содержимое файла — проверяемая проекция
  фактически отправленного контекста.

**Архитектурная гарантия:** запрос к облачной модели конструирует только
прокси. Локальная модель в LM Studio используется исключительно для NER —
она возвращает список сущностей (JSON) и не формирует никаких запросов
в облако.

### Процесс анонимизации

0. **Извлечение приложенных файлов** (оба режима):
   - Если клиент (Cline) приложил файл, но не смог его прочитать (типично для
     бинарных документов DOCX/XLSX), в тексте сообщения появляется блок
     `<file_content path="...">Error fetching content: ...</file_content>`
   - Прокси обнаруживает такие блоки, сам читает локальный файл по указанному
     пути (поддерживаются абсолютные пути, относительные от корня workspace
     и `file://` URI) и извлекает текст через `FileParser`
     (DOCX/XLSX/XML/TXT/MD)
   - Извлечённый текст подменяет заглушку-ошибку и дальше участвует в NER и
     анонимизации наравне с остальным текстом запроса
   - Если файл не найден или формат не поддерживается — блок остаётся без
     изменений, запрос не падает (в лог пишется предупреждение)
   - Извлечение через `FileParser` — **основной механизм** попадания содержимого
     офисных документов в анонимизацию: успешно прочитанные клиентом
     `<file_content>`-блоки не подменяются; маппинги общие для сессии, поэтому
     одна и та же PII получает один и тот же плейсхолдер
   - Для DOCX и XLSX `FileParser` сохраняет простейшую структуру: абзацы и
     таблицы Word, листы и ячейки Excel. Обратная сборка (`FileAssembler`,
     эндпоинт `/api/anonymize`) записывает анонимизированный текст обратно
     по координатам сегментов: сетка таблиц сохраняется, а неизменённые
     ячейки (включая формулы, числа и даты Excel) не затрагиваются
1. **NER** (Named Entity Recognition):
   - Использует локальную модель в LM Studio (`qwen/qwen3.5-9b`)
   - Выявляет PII: имена, должности, организации, телефоны, email, ИНН, адреса, суммы
   - Поддержан **thinking-режим** модели: если итоговый ответ в `content` пуст,
     прокси ищет JSON с сущностями в `reasoning_content` (берётся последний
     JSON, промежуточные игнорируются)
   - Модель возвращает только текст и тип сущностей; **оффсеты в тексте
     вычисляет сам прокси** (точное совпадение + поиск без учёта регистра
     и различия ё/е) — ошибки модели в оффсетах больше не теряют сущности
   - Для оргформ с названием в кавычках (`ООО «ИРИС»`) прокси дополнительно
     выделяет ядро (`ИРИС`) и заменяет также все короткие вхождения названия
     — разрозненные упоминания одной компании не утекают в облако
   - Поиск сущностей устойчив к написанию: регистр, ё/е и визуально одинаковые
     буквы кириллицы/латиницы (`«1С»`/`«1C»`) считаются совпадением —
     значение, возвращённое моделью в одном алфавите, покрывает вхождения
     в другом
   - Промпт требует помечать в том числе широко известные организации,
     госорганы, имена с инициалами и все варианты названия одной компании;
     итоговое качество детекции зависит от локальной модели
   - Текст длиннее `NER_MAX_INPUT_CHARS` (по умолчанию 128000 символов —
     лимит по VRAM) разбивается на чанки с перекрытием 500 символов;
     сущности переносятся в координаты исходного текста, поэтому границы
     чанков не теряются. Чанки обрабатываются последовательно по умолчанию;
     число одновременных NER-запросов задаёт `NER_PARALLEL` (по умолчанию 1 —
     конкурентные запросы к LM Studio могут вешать модель). Короткие тексты
     идут одним вызовом
   - Если LM Studio недоступна или NER-запрос оборвался (соединение разорвано,
     нет JSON в ответе), LLM-детекция считается **невыполненной**: при
     анонимизации файла прокси возвращает явную ошибку, а не молча «0
     сущностей» — файл не будет выглядеть анонимизированным, когда это не так
   - Детерминированная страховка: оргформы (ООО/АО/ПАО/ОАО/ЗАО/НКО/НПФ/ГК,
     Фонд/Банк + название) ловятся regex с учётом регистра даже если LLM
     их пропустила
2. **Замена**:
   - PII заменяется плейсхолдерами вида `[Имя_1]`, `[Организация_1]`, `[Телефон_1]`
   - Если значение признано PII хотя бы один раз, заменяются **все** его
     точные вхождения в тексте (LLM часто пропускает повторные упоминания);
     одно и то же значение всегда получает один и тот же плейсхолдер
   - Маппинги сохраняются в SQLite (`anonymizer.db`) с TTL 24 часа
3. **Отправка в облако**:
   - Анонимизированный запрос отправляется в OpenRouter
   - Модель генерирует ответ (без знания реальных данных)
4. **Де-анонимизация**:
   - Ответ от OpenRouter проходит обратную замену плейсхолдеров на реальные значения
   - Возвращается клиенту

### Хранение данных

- **БД**: `anonymizer.db` (SQLite) — маппинги, логи
- **Логи**: `data/logs/` — JSON-логи запросов/ответов
- **Анонимизированные файлы**: `data/anonymized_files/`
- **Маппинги**: `data/mappings/` — временные файлы с TTL

## Конфигурация (.env)

> **Важно:** скопируйте `.env.example` в `.env` и заполните своими значениями.
> Файл `.env` и каталог `data/` (содержит PII!) исключены из git через `.gitignore`.

```ini
# OpenRouter API ключ (получить на https://openrouter.ai/keys)
OPENROUTER_API_KEY=sk-or-v1-...

# Модель в OpenRouter (должна существовать в OpenRouter)
OPENROUTER_MODEL=qwen/qwen3.7-plus

# LM Studio (локальная NER-модель)
LM_STUDIO_URL=http://localhost:1234/v1
LM_STUDIO_MODEL=qwen/qwen3.5-9b

# Параметры NER (локальная модель):
# Максимальный размер текста (символы), отдаваемый NER-модели за один вызов —
# задавайте по вместимости VRAM/контекста, с запасом на промпт и ответ.
# Текст длиннее автоматически режется на чанки с перекрытием 500 символов.
NER_MAX_INPUT_CHARS=128000
# Лимит токенов ответа NER (список сущностей большого документа велик)
NER_MAX_TOKENS=16384
# Таймаут NER-запроса в секундах (обработка больших документов долгая)
NER_TIMEOUT_SECONDS=600
# Число одновременно обрабатываемых NER-чанков (параллелизм). По умолчанию 1
# (последовательно): конкурентные запросы к LM Studio могут приводить к
# зависанию модели — не повышайте без нужды.
NER_PARALLEL=1

# Прокси для OpenRouter (Happ VPN)
OPENROUTER_PROXY=http://127.0.0.1:10809

# Настройки прокси
# По умолчанию сервер слушает ТОЛЬКО localhost (127.0.0.1).
# Для 0.0.0.0 ОБЯЗАТЕЛЬНО задайте PROXY_API_TOKEN — иначе сервер не запустится.
PROXY_HOST=127.0.0.1
PROXY_PORT=8081

# Токен доступа к административным /api/* эндпоинтам (логи, де-анонимизация,
# экспорт, статус, cleanup). Передаётся заголовком:
#   Authorization: Bearer <token>   или   X-API-Key: <token>
# Генерация: python -c "import secrets; print(secrets.token_urlsafe(32))"
PROXY_API_TOKEN=<сгенерируйте случайный токен>

# Режим работы: full, anonymize_only или passthrough
# full - полная обработка: анонимизация → облако → де-анонимизация
# anonymize_only - только анонимизация без отправки в облако (возвращает фиктивный ответ)
# passthrough - явное управление: запросы Cline идут без анонимизации (основной)
ANONYMIZER_MODE=passthrough

# Keep-alive во время подготовки (NER): прокси периодически отдаёт клиенту
# нейтральные SSE-комментарии, пока идёт анонимизация, чтобы клиент не считал
# запрос зависшим. Отключить: KEEPALIVE_ENABLED=false.
KEEPALIVE_ENABLED=true
KEEPALIVE_INTERVAL_SECONDS=3

# Уровень логирования: DEBUG, INFO, WARNING, ERROR
LOG_LEVEL=INFO

# Исключаем localhost из VPN
NO_PROXY=localhost,127.0.0.1,::1
```

**Важно**: прокси использует **только** эти настройки. Параметры из Cline (модель, API-ключ) **игнорируются**. Cline просто отправляет запрос на `http://127.0.0.1:8081/v1/chat/completions`, а прокси подставляет свои реальные значения из `.env`.

## API эндпоинты

### OpenAI-совместимые

| Метод | Путь | Описание |
|-------|------|----------|
| **POST** | `/v1/chat/completions` | Chat completions (анонимизация → облако → де-анонимизация) |
| **GET** | `/v1/models` | Список моделей (проксирует от OpenRouter) |

### Внутренние

Все эндпоинты `/api/*` требуют токен (`PROXY_API_TOKEN`), если он задан:
заголовок `Authorization: Bearer <token>` или `X-API-Key: <token>`.

| Метод | Путь | Описание |
|-------|------|----------|
| **GET** | `/health` | Проверка работоспособности (LM Studio, режим) |

## Как Cline с ним работает

1. **Настройки Cline**:
   - **Base URL**: `http://127.0.0.1:8081/v1`
   - **API Key**: любой (прокси игнорирует)
   - **Модель**: любая (прокси подставляет свою из `.env`)
   - **Stream**: `true` (поддерживается)

2. **Что происходит**:
   - Cline отправляет запрос → прокси принимает его
   - Подставляет реальные значения из `.env` (модель, API-ключ, прокси)
   - Анонимизирует запрос через LM Studio (во время NER прокси отдаёт
     keep-alive SSE-комментарии, чтобы Cline не считал запрос зависшим)
   - Отправляет в OpenRouter через VPN-прокси
   - Де-анонимизирует ответ и возвращает Cline

3. **Ручное управление анонимизацией** — см. раздел «Ручное управление
   анонимизацией» ниже (инструменты плагина / эндпоинты / расширение).

## Требования к настройке LM Studio

Локальная модель в LM Studio выполняет NER (анонимизацию). Требования:

1. **Сервер**: LM Studio запущен, локальный сервер включён на
   `LM_STUDIO_URL` (по умолчанию `http://localhost:1234`, путь `/v1`),
   OpenAI-совместимый API отвечает на `GET /models` и
   `POST /chat/completions`.
2. **Модель**: для NER загружена модель, и значение `LM_STUDIO_MODEL` в `.env`
   **точно совпадает** с её идентификатором в LM Studio (см. список в
   `GET http://localhost:1234/v1/models`). По умолчанию `qwen/qwen3.5-9b`.
3. **Thinking-режим** (рассуждения модели): поддерживается прокси в обоих
   состояниях — и включён, и выключен.
   - При включённом thinking итоговый ответ приходит в `content`, а
     рассуждения — в `reasoning_content`; если `content` пуст, прокси
     разбирает `reasoning_content`.
   - **Reasoning budget** (настраивается в LM Studio для модели): должен быть
     достаточным, чтобы модель успевала выдать итоговый JSON с сущностями.
     Если бюджет мал, ответ обрезается (`finish_reason=length`), JSON не
     появляется, и прокси пишет в лог предупреждение
     «LM Studio не вернул JSON с сущностями…» — увеличьте Reasoning budget
     или `NER_MAX_TOKENS` в `.env`.
4. **Контекст**: окно контекста модели должно вмещать `NER_MAX_INPUT_CHARS`
   символов текста плюс запас на системный промпт и ответ
   (`NER_MAX_TOKENS`). Текст длиннее автоматически режется на чанки
   с перекрытием.
5. **Таймаут**: обработку больших документов локальной моделью ограничивает
   `NER_TIMEOUT_SECONDS` (по умолчанию 600 с). Thinking-режим заметно
   увеличивает время ответа — закладывайте это в таймаут.
6. **Параллелизм чанков**: длинный текст режется на чанки; число одновременных
   NER-запросов задаёт `NER_PARALLEL` (по умолчанию 1 — последовательно).
   Повышать параллелизм не рекомендуется: конкурентные запросы к LM Studio
   (0.4.x) могут приводить к зависанию модели («Channel Error» после обрыва
   соединения). Если всё же включаете — нужен движок llama.cpp/GGUF и
   «Max Concurrent Predictions» ≥ 2 (Model loader → Show advanced settings);
   запросы сверх лимита встают в очередь.

## Ручное управление анонимизацией

В явной схеме (`ANONYMIZER_MODE=passthrough`) анонимизация выполняется
отдельными шагами через эндпоинты `/api/*`:

| Метод | Путь | Назначение |
|-------|------|------------|
| POST | `/api/anonymize` | Анонимизировать текст (без облака), вернуть `.md` |
| POST | `/api/anonymize_file` | Анонимизировать локальный файл: создать копию `<name>.anonymized.<ext>` + `.md` для review |
| POST | `/api/send` | Отправить анонимизированный промпт в облако, вернуть де-анонимизированный ответ |
| POST | `/api/deanonymize_file` | Заменить плейсхолдеры в файле на реальные значения (финальный шаг) |
| GET | `/api/sessions` | Список активных сессий |
| POST | `/v1/chat/completions` с `anonymize: false` | Отправить промпт сразу в облако без анонимизации |

Файлы (DOCX/XLSX) извлекаются в **markdown с таблицами** — и для review, и для
отправки в облако. Модель правит документ через анонимизированную копию и
пишет результат в файл результата `<name>.result.<ext>`, а де-анонимизация
выполняется в самом конце.

### Использование в интерфейсе

Основной интерфейс — **Cline** (обычный чат, без обязательных плагинов).
Прокси сам перехватывает команды анонимизации/де-анонимизации по тексту
запроса, поэтому пользователь просто пишет промпты на естественном языке.

1. **Анонимизировать файл** — «Анонимизируй приложенный файл» → прокси
   анонимизирует файл локальной NER-моделью, создаёт копию
   `<name>.anonymized.<ext>` рядом с оригиналом и возвращает `session_id`.
   В облако ничего не уходит.
2. **Проверить/отредактировать** — пользователь правит **анонимизированную
   копию в исходном формате** (структура и таблицы DOCX/XLSX сохраняются);
   исходный файл не изменяется.
3. **Работа с файлом в облаке** — пользователь продолжает тот же чат; модель
   читает копию, а прокси извлекает из неё текст и передаёт в облако; текст
   ответа де-анонимизируется автоматически (аргументы правок файла — нет).
   **Отдельной команды «отправить в облако» не существует** — облако
   используется автоматически, достаточно просто написать задачу для
   документа («добавь колонку в таблицы», «составь резюме» и т.п.).
   **При изменении документа модель не трогает копию** (она остаётся
   исходником) — результат правок пишется в отдельный файл
   `<name>.result.<ext>` рядом с копией.
4. **Финальная де-анонимизация** — «Деанонимизируй упомянутые файлы» → прокси
   заменяет плейсхолдеры в **файле результата** реальными значениями. Если
   модель не создала файл результата, а правила анонимизированную копию на
   месте — де-анонимизируется копия (fallback), чтобы поток всегда давал
   готовый документ.

Опционально доступен **Cline SDK-плагин** (`cline-plugin/`) с инструментами
`anonymize_text`, `anonymize_file`, `send_prompt`, `deanonymize_file` — для тех,
кто предпочитает явный пошаговый вызов вместо естественных команд. Установка:
см. `cline-plugin/README.md`.

**Правило для модели.** Чтобы модель надёжно соблюдала конвенцию «копия —
исходник, правки — в файл результата», в корне проекта лежит `.clinerules`
(попадает в системный контекст Cline): анонимизированную копию не изменять,
результат писать в `<name>.result.<ext>`, плейсхолдеры сохранять. Прокси, со
своей стороны, страхует поток fallback-де-анонимизацией.

## Что нужно помнить

1. **Модель в .env** должна точно совпадать с существующей в OpenRouter (например, `qwen/qwen3.7-plus`).
2. **VPN-прокси** обязателен для OpenRouter (Happ на `127.0.0.1:10809`).
3. **LM Studio** должен быть запущен на `localhost:1234` (для NER); модель и
   Reasoning budget должны соответствовать разделу «Требования к настройке
   LM Studio» (иначе в thinking-режиме ответ будет обрезан и сущности
   не извлекутся).
4. **Cline** настраивается на `http://127.0.0.1:8081/v1` и игнорирует реальные модели/ключи.
5. **Логи** помогают отлаживать проблемы (print + файлы).
6. **Изменения в `.env`** (включая `ANONYMIZER_MODE`) применяются только после
   перезапуска прокси. Если поведение не изменилось — проверьте, что старый
   процесс остановлен, а новый запущен (эндпоинт `/health` показывает текущий режим).

## Диагностика

- **HTTP 500** — неправильное имя модели: проверьте `OPENROUTER_MODEL` в `.env`
  (модель должна существовать в OpenRouter, например `qwen/qwen3.7-plus`).
- **HTTP 403 «Access denied»** — отсутствие VPN-прокси для OpenRouter: задайте
  `OPENROUTER_PROXY=http://127.0.0.1:10809`.
- **«Сущностей 0, PII не заменены»** (thinking-режим) — локальная модель не
  успела выдать JSON сущностей: увеличьте Reasoning budget в LM Studio или
  `NER_MAX_TOKENS` в `.env` (см. «Требования к настройке LM Studio»).
