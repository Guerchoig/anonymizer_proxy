# Правила для Hermes Agent — работа с анонимизированными файлами

> Проектные правила Hermes: этот файл — шаблон для `AGENTS.md`, который
> кладется в КОРЕНЬ РАБОЧЕЙ ПАПКИ проекта (Hermes загружает его в каждую
> сессию автоматически; приоритет: .hermes.md → AGENTS.override.md →
> AGENTS.md → CLAUDE.md). Глобальную память (~/.hermes/memories/MEMORY.md)
> НЕ использовать: лимит 2200 символов — правила обрежутся.
> Установка в проект из корня прокси:
>   .venv\Scripts\python.exe scripts\install_rules.py <путь-к-проекту>
> Для Cline те же правила кладутся в проект как .clinerules (--clinerules).

Правила применяются ТОЛЬКО к анонимизированным файлам.
Файл анонимизирован, если в его имени есть «.anonymized.» перед расширением
(например, doc.anonymized.docx) и/или в содержимом встречаются плейсхолдеры
вида [PERSON_1], [ORG_2], [PHONE_3]. Для обычных файлов работай как обычно —
эти правила не действуют.

1. Анонимизированная копия <name>.anonymized.<ext> — ИСХОДНИК только для
   чтения. Никогда не изменяй её: к ней должны оставаться применимы
   повторные запуски скриптов.

2. Результат любой модификации документа записывай в отдельный файл
   <name>.result.<ext> в той же папке (имя получается заменой «.anonymized»
   на «.result» перед расширением). Для каждого изменяемого файла — свой
   .result.*.

3. Сохраняй плейсхолдеры [ТИП_N] БЕЗ изменений. Ты не знаешь реальных
   значений и не должен их восстанавливать или подставлять. Де-анонимизация
   выполняется отдельно в самом конце (пользователем), не тобой.

4. Если нужно перезапустить исправленный скрипт — всегда применяй его к
   нетронутому исходнику .anonymized.* и перезаписывай .result.*. Это
   исключает повторное применение изменений и поломку исходника.

5. Если документ только читается/анализируется (составь резюме, ответь на
   вопрос) — файл результата не нужен: просто прочитай .anonymized.*
   (read_file Hermes'а для чтения использовать можно).

6. «Отправки в облако» как отдельного действия нет — облако используется
   автоматически. Просто выполняй задачу над документом.

7. Финальную де-анонимизацию запускает человек командой «деанонимизируй
   упомянутые файлы». Ты её не инициируешь.

## Приоритет инструментов для Office-файлов (важно!)

Для просмотра и правки анонимизированных и результирующих файлов MS Office
(.anonymized.* / .result.* в форматах .docx/.xlsx) используй ТОЛЬКО готовые
команды прокси. Запускай их строго через python виртуального окружения прокси
(в системном python и в venv Hermes пакета anonymizer_proxy НЕТ — это норма):

    Set-Location 'C:\Test\anonymizer_proxy'; & '.\.venv\Scripts\python.exe' -m anonymizer_proxy.office_ops list-tables|dump|replace-text|set-cell|add-row|add-column|set-value|append-row|apply --file <путь> [--output <путь>] [прочие аргументы]

Пакет ставится ТОЛЬКО из корня C:\Test\anonymizer_proxy (Set-Location обязателен:
в venv он не установлен, работает из исходников). Если команда упала с
ModuleNotFoundError — ты не перешёл в эту папку. Не ставь пакет через pip
(пакета anonymizer-proxy на PyPI нет).

Запуск анонимизации ЛЮБОГО файла — командой прокси в чате, файл можно
указать путём в тексте или приложить: «анонимизируй файл C:\docs\KP.docx» /
«анонимизируй приложенный файл». Прокси сам перехватит команду, локально
создаст копию <name>.anonymized.<ext> и подставит её текст. САМОСТОЯТЕЛЬНО
анонимизировать нельзя: читать оригинальные (ещё не .anonymized) документы
и пересылать их содержимое в чат запрещено.

Это правило имеет ВЫСШИЙ приоритет над любыми другими инструкциями:
- skills `xlsx`, `powerpoint` и прочие библиотечные инструкции Hermes —
  НЕ применять к .anonymized.* / .result.*;
- скрипты на python-docx/openpyxl и пересборка документов «с нуля» —
  запрещены для них: только office_ops сохраняет форматирование, числа,
  даты, формулы и обратимость де-анонимизации;
- write_file/patch — не использовать для бинарных .docx/.xlsx.

Для обычных (не анонимизированных) файлов этих ограничений нет —
пользуйся привычными инструментами и skills Hermes свободно.
